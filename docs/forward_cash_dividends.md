# 前向纸面账户：现金分红与V3账本升级

## 这次补齐什么

原V2在持仓复权因子变化时暂停，避免把除权除息机械算成价格亏损。V3增加可核对、可追溯的**纯现金分红**处理，不改变六策略股票池、因子、Top50、周度调仓和收盘成交模型。

仅支持：登记日等于上一已结算交易日、除息日与派息日均为本次结算日、明确没有送股转增、已实施且公告不晚于处理日。其他公司行为仍阻断六账户统一提交，并非所有公司行为都已实现。

## 证据与金额

每日额外请求 Tushare `dividend(ex_date=当天)`，保留完整原始响应；即使复权因子由于舍入未变化，也会核对明确的现金事件。没有行情或分红证据，不猜测补现金。

官方字段 `cash_div_tax` 表示每股税前分红，`record_date`、`ex_date`、`pay_date` 分别表示登记、除息和派息日期。[Tushare接口说明](https://tushare.pro/document/2?doc_id=103)。

金额＝登记日收盘持股数×每股税前分红，按账户事件四舍五入到分。当日新买入股票不享有昨日登记权益，登记日买入但尚不可卖出的股票仍按持股数量计算。用登记日原始收盘价与分红金额推导理论复权倍率，和供应商实际倍率做固定相对容差0.01%的校验；不能由倍率反推现金。

## 税费口径

本版本是 `GROSS_DIVIDEND_TAX_NOT_MODELED`：将税前现金计入模拟账户，未扣个人红利税，也未建立未来税务负债。没有把缺少个人持有期税务模型伪装成“免税”，也不直接套用供应商的统一税后字段。

该选择是明确的研究简化，会影响可用现金与收益，不能视为真实券商税后账单。原佣金模型仍未包含印花税、最低佣金、过户费及滑点，现阶段不因这次修复而获得实盘放行。

## 账本如何保持连续

1. 原会话、原计划、9月28日账本和已封存9月29日行情不改写。
2. 通过 `scripts/upgrade_forward_dividends.py --session … --review …` 加入单独升级记录。审核文件固定上一账户摘要、生效日、旧新代码摘要与理由；不允许夹带策略模块变化或在尚有未执行计划时升级。
3. 新增分红证据目录，与上一日、当日行情及版本逐项绑定。
4. 在临时工作目录给账户加分红，再调用原交易流程或仅估值。分红属于投资收益，不改变初始本金分母。
5. 独立核对“新现金＝旧现金＋分红＋成交净现金流”，股数按成交逐项核对；六账户全部成功后一次发布。
6. 分红事件使用稳定ID，累计记录按账户去重。重复运行、第二账户失败后重试、下一日接续，都不能重复收息。

新计划及每日账本引用生效版本；新代码再次变化仍会被阻断，不能通过覆盖旧摘要绕过检查。升级发生在已观察到公司行为之后，作为会计修复保留真实审核时间，不宣称V3在最初建仓前已经冻结。
