# 六策略前向纸面交易：每日操作与故障处理

新会话：`output/six_strategy_forward_20260928`。旧会话 `output/six_strategy_forward_paper` 保留为9月24日初始化回放，禁止拼接净值。

所有命令均从项目根目录运行。本流程只操作虚拟账户，不连接真实券商，不含自动定时任务。

## 1. 今天已经冻结什么

策略规则沿用第124篇：六策略独立、100万元/账户、Top50等权、周度调仓、下一交易日收盘理想化模拟。新的版本改变的是冻结时间、数据验证、板块数量规则与账本提交方式，不重新挑选收益更好的因子。

准备期只有现金账户和目标清单，没有未来成交、没有未来净值。

```sh
.venv/bin/python scripts/run_forward_ledger.py status \
  --session output/six_strategy_forward_20260928
```

首次建立会话使用 `run_forward_ledger.py init`，已有会话不能再次 init。计划文件不允许覆盖，也没有 `--allow-rerun` 或伪造时间参数。

## 2. 每个交易日收盘后运行一次

例如9月28日收盘且供应商行情完整后：

```sh
MPLCONFIGDIR=/tmp/quant_strategy_mpl .venv/bin/python scripts/run_forward_daily_with_records.py \
  --session output/six_strategy_forward_20260928 \
  --data-dir data/all_a_forward_20260927 \
  --date 2026-09-28 \
  --prompt-token
```

Token 在隐藏输入框输入，仅进入当前进程环境；已有 `TUSHARE_TOKEN` 时省略 `--prompt-token`。不要放入命令行参数、版本库、文章或日志。

有人工风险黑名单时显式传 `--blacklist data/risk_blacklist.csv`。不传时快照明确写 `EXPLICIT_EMPTY_NOT_CONFIGURED`，这不是“所有新闻事件已通过”。不能在有真实黑名单的情况下故意不传。

日常入口依次：检查交易日与收盘时间；读取上一已提交交易日账户；获取目标与持仓的当日行情、涨跌停、停牌、复权因子；执行当天已冻结调仓计划或仅记账；校验资金、持仓；六账户一次性提交。周末节假日不会多记净值。

周内普通日不会因为权重漂移而每天买卖。未成交订单当日失效，不在之后每日偷偷追单；等下一次周度计划再决定。缺少应有周度计划时暂停，而不是擅自继续持有并声称正常执行。

周度最后交易日完成记账后，入口会更新研究数据并为下一交易日冻结新计划。按当前日历，9月30日之后的下一交易日为10月8日；不能机械地把“每周五”或“明天”当成调仓日期。

## 3. 检查输出

每天优先打开[每日持仓与交易目录](../output/six_strategy_forward_20260928/reports/daily_records/README.md)。其中每个交易日一份 `YYYY-MM-DD.md`，按六个账户列出全部实际持仓、股数增减、估值与权重、逐笔买卖和佣金、未成交原因及分红；无交易日明确写无成交。

新增入口 `run_forward_daily_with_records.py` 先调用原样保留的冻结入口 `run_forward_daily.py`，随后自动导出阅读副本；若日账本已提交、后续周度准备失败，也会尝试导出并继续报告原失败。原入口在冻结指纹范围内，没有为文档功能修改它。包装入口不改变策略、账户或成交；重复运行不会再次交易。这里的“自动”指每次实际调用新入口时生成，不代表已安装每日定时任务。导出冲突会报错，但此前已提交的日账本保留，不应因此重置账户。

也可单独补齐所有已完成交易日，不联网、不需要Token：

```sh
MPLCONFIGDIR=/tmp/quant_strategy_mpl .venv/bin/python scripts/export_forward_daily_records.py \
  --session output/six_strategy_forward_20260928
```

文档和目录有人工修改时拒绝覆盖，请将个人笔记另存。尚未结算的日期、休市日不生成文档。阅读副本与源账本都位于本地忽略的 `output/`，不会因为提交代码而自动公开。

- `initial/`：最初纯现金状态、策略协议、交易日历、执行模型说明和代码指纹。
- `plans/YYYYMMDD/`：对应执行日的冻结清单、信号日行情、股票池审计、输入数据指纹。
- `market/YYYYMMDD/`：供应商原始响应、严格日期状态和黑名单快照。
- `corporate_actions/YYYYMMDD/`：V3现金分红原始证据与校验后的事件，独立封存，不改旧行情快照。
- `revisions/cash_dividend_v1/`：显式审核的账本升级记录，连接原会话、上一日账户与新代码指纹。
- `days/YYYYMMDD/`：该日六账户的完整状态、持仓、累计快照、订单、检查、模拟成交及汇总。
- `reports/`：阅读版清单与图；不作为下单或账户状态输入。
- `reports/daily_records/`：每日持仓及逐笔交易文档，`README.md`为日期索引。

每一日记录引用上一日记录的摘要。下一天从上一天完整保存的现金和持仓接续，不回到100万元重新开局。修改历史文件后校验会失败；摘要用于完整性核验，不是第三方公证时间戳。

## 4. 异常处理

- **行情未完整返回**：等待供应商补齐后重试。缺少日线不等于停牌，禁止旧价格冒充当日成交。
- **停牌**：必须有供应商明确停牌记录；保留持仓，用可追溯的上一估值价记账，并阻止买卖。该价格不是当日可成交价格。
- **当天已完成**：日常入口不会再次交易；如果上次仅周度计划准备失败，可重试完成计划。底层 `day` 命令重复调用则明确报错。
- **第二个或之后账户报错**：未完成的数据留在临时工作阶段，不发布部分账本；修复后重试。机器异常退出可能留锁，先确认无运行进程再人工处理该特定锁目录，不要重置账户。
- **漏记交易日**：先补齐缺失日的账户连续记账。已经提前冻结的旧计划可延迟入账，须保留实际处理时间；不能在错过执行时点后补造新计划并称其为前向。
- **发现持仓复权因子变化**：V2继续暂停；明确升级后的V3仅支持上一交易日登记、当天除息且当天派息的纯现金分红。实施记录须解释因子变化，按登记日已持股数入账。送转、配股、延后派息、日期不符或金额矛盾继续暂停，不用复权价掩盖损益。见[现金分红与升级说明](forward_cash_dividends.md)。
- **代码或策略规则变了**：停止并版本化复核，不直接修改已冻结会话的指纹绕过检查。
- **交易日历覆盖结束**：当前冻结日历覆盖到2027年1月2日；超出范围会暂停，需要复核延期方案，不按工作日猜测开市。

## 5. 仍然不是实盘系统

成交模型使用当日未复权收盘价估算数量和成交，是理想化收盘模型，不是收盘前确定股数的真实订单撮合。暂不模拟排队、部分成交、滑点、成交量冲击。

费用继续沿用原研究的单边0.03%佣金简化口径，未纳入最低佣金、印花税、过户费，不能直接拿净值当成实盘净收益。证券代码与板块权限是研究口径，不代表用户账户可买创业板或科创板。

V3分红按税前金额入账，累计事件保存在每日目录的 `dividends.csv`，每日汇总增加 `dividend_cash_gross` 与 `dividend_tax_policy`。未模拟个人持有期差异化红利税、后续卖出补税或应付税准备，因此净值是含税前分红的研究口径，不能称为完整税后收益。没有将派息记为外部入金，也不会重置初始本金。

基础股票池硬风险、有效黑名单、停牌涨跌停、数量、资金、时间和账本完整性参与检查。统一公告新闻门禁、组合压力降仓等没有自动变成实盘放行条件；报告明确未评估，不写虚假的 PASS。

## 6. 调仓日只读复盘

日账本提交之后，后续调仓日使用独立报告入口（首日建仓和普通持仓日各有原报告工具）：

```sh
MPLCONFIGDIR=/tmp/quant_strategy_mpl .venv/bin/python scripts/build_forward_rebalance_report.py \
  --session output/six_strategy_forward_20260928 \
  --date 2026-10-08 \
  --output output/six_strategy_forward_20260928/reports/20261008_close
```

示例日期结果已存在，不重复覆盖。新的报告必须使用不存在的输出目录。工具校验封存账本和冻结计划，按“旧持股价格损益＋分红－佣金”核对当天损益，按逐笔成交核对股数和现金，保存收益、买卖、阻断订单、现金与图片。它不获取行情、不执行交易、不回写目标或账户，也不把新买入股票记为享有收盘前收益。
