# 七篇论文研究成果：主分支选择性集成与验收

日期：2026-10-09。

这次带回主分支的是**研究检查工具**，不是七套新交易策略。目标是让工程更容易发现数据时间错误、收益来源误读和反复试验挑冠军的问题，不承诺提高回测收益。

## 1. 这次实际合并了什么

采用选择性代码迁移：从 `codex/quant-paper-lab` 工作区提取通用部分，整理为主分支模块；不是将整个研究分支直接 `git merge`。论文原脚本、原协议和原结果继续保留在研究工作区，主分支已有未提交内容没有被覆盖。本轮未提交或推送 Git。

### 第二讲：收益来源与不确定性

新增 `analysis/return_attribution.py`，提供带 Newey-West/HAC 标准误的收益回归、剩余均值项区间以及算术平均收益分解。

它补充而不替代已有 `analysis/style_exposure.py`：已有模块观察持仓偏向哪些风格；新模块观察收益变化与传入的市场、规模、价值代理之间的关系。R²不是利润占比，更不代表预测能力；剩余均值项也不是已经证明的选股能力。

只接入通用回归，不接入第二讲那套特定股票池、特定分组阈值的风格指数构建器。归因所需的代理序列必须显式提供。本次历史验收使用第二讲已封存的本地代理，不是官方 Fama-French 数据。

### 第三讲：按当时可见价格计算信号

新增 `analysis/signal_asof.py`：显式指定回看长度、跳过多少期、正向动量或反向反转；只使用信号日及此前价格；多个信号共用当时可用的样本。

与论文脚本相比，去掉了自动追加特定融合信号的逻辑。它现在是供新研究调用的纯函数，不自动注册因子，也不替换当前六策略的动量和反转定义。

### 第四讲：年度财务数据可见性

新增 `analysis/financial_asof.py`：年度利润表与资产负债表按公告时间和相同年报期配对；采用公告日、实际公告日中的较晚日；保守地排除信号当天刚公告的数据；同一版本有冲突时标记无效；畸形日期拒绝处理。

这里没有顺便加入“盈利必须为正”等股票池过滤，也没有启用毛利润/总资产因子。它目前支持指定字段的年度两表配对，不是完整三表数据平台。

重要限制：这能防止把**已知晚公告的数据**提前使用，却不能把供应商今天下载的历史表自动变成不可修改的历史版本库。

### 第六讲：同时试很多方案时的统计修正

新增 `analysis/research_statistics.py`：主动收益均值的 HAC 标准误、置信区间、正向单侧检验，以及 Bonferroni、Holm、BH、BY 调整。

主分支只保留一份多重检验算法；收益归因也复用它，避免第二讲与第六讲各维护一套 Holm。已有 `analysis/factor_validation.py` 继续负责原来的样本外和滚动验证，新模块不取代原制度。

### 第七讲：历史冠军的排序稳定性

新增 `analysis/selection_diagnostics.py`：CSCV 组合对称交叉验证，分别报告训练冠军在测试部分严格低于中位数、恰好处于中位数，以及包含并列的 PBO。

CSCV不是严格按时间前后排列的前向检验，PBO不是未来亏损概率。没有迁入“每隔一段时间自动选择历史冠军”的交易策略。

## 2. 如何在工程里使用

统一入口是 `scripts/run_research_audit.py`，报告组装在 `analysis/research_audit.py`。

流程为：已有净值与各自基准 → 显式声明候选集和输入哈希 → 只读统计检查 → 新目录内的 JSON 与中文 Markdown 报告。

它不导入交易执行模块，不读取 Token，不请求行情，不写持仓和订单，也不修改因子准入状态。主流程、每日前向交易入口都没有强制调用它。后续回测可以在完成后独立调用；不能把“有这个工具”理解为所有历史数据已被自动检查。

时间检查函数用于有原始价格、财务数据的新研究；仅给净值的报告明确标记 `NOT_ASSESSED_FROM_NAV`，不会假称验证过点时点数据。

### 输入约定

- 净值文件：CSV，唯一且升序的 `date` 列，策略与基准各占一列，完整、有限、严格为正；不自动补缺失值。
- `pairs`：每个策略对应自己的点时点适用池基准，不能为了结果好看随意换基准。
- 声明日频、小数收益单位、成本口径，以及候选家族范围。程序无法知道用户是否遗漏了失败试验，报告会提醒这一限制。
- 可选归因代理：日收益 CSV；显式声明归因区间，日期必须完全对齐，不偷偷取交集。当前接口使用传入收益，不自动扣无风险利率。
- 可选 CSCV：显式声明起止日和块数；不为凑整静默删除日期。组合数量上限为 20,000，防止误配置造成不可控计算。
- 输入文件须声明 SHA-256；执行前核对，执行后再次确认未变；每次输出必须是新目录。

输入规格结构示例（路径、哈希、列名及日期须换成实际数据）：

```json
{
  "frequency": "daily",
  "return_units": "decimal",
  "family_description": "事先声明的所有候选方案，不只保留赢家",
  "cost_convention": "净值已扣除本次回测声明的交易成本",
  "nav": {"path": "nav.csv", "sha256": "填写文件实际SHA-256"},
  "pairs": {"strategy_a": "benchmark_a", "strategy_b": "benchmark_b"},
  "options": {"lags": 5}
}
```

运行方式：

```bash
.venv/bin/python scripts/run_research_audit.py \
  --spec /绝对路径/研究输入规格.json \
  --output output/新的研究检查目录
```

报告包含 `report.json`、`README.md`、输入规格副本和输出哈希清单。JSON保留系数、收益贡献、来源和代码哈希，Markdown供日常阅读。样本少于60条或方差退化时，统计项明确显示“未评估”，不是通过，也不自动禁用。60条只是计算底线，不是足以证明有效的样本量。

有候选无法计算时，多重调整仍保留整个声明家族的大小；不可评估项内部以保守占位处理，不通过删除失败项降低惩罚。

## 3. 怎么验证它确实有作用

### A. 公式与故障注入：新增36项测试

包括独立矩阵公式核对 HAC、已知 p 值校正、训练/测试排名与并列处理，以及以下故意制造的错误：

- 大幅修改未来价格，过去信号必须不变。
- 增加未来公告的财报修订，不能改变此前读取的财务值。
- 同一天公告、不一致年报期、冲突版本、错误日期不能被当成正常可用数据。
- 缺失净值、日期错位、重复文件列名、哈希不符必须报错。
- 仅有几天的前向收益不能产出“通过验证”的结论。
- 同一输入两次生成内容一致；已有报告目录拒绝覆盖。

主分支全量 `unittest` 验收：**378项通过**，其中本次新增36项。

### B. 旧结果迁移一致性：两组研究分开复核

验证脚本为 `scripts/verify_paper_research_merge.py`。它先核对研究分支的原始输出清单，再通过新入口复核。固定归档路径仅存在于这份迁移验收适配器，不存在于通用工具中。

**原六策略收益归因**：重现第二讲的累计收益、基准差距、R²、剩余均值项及其区间、Holm调整结果。归因指标最大绝对误差约 `1.87e-14`，属于浮点舍入差异。六个剩余均值项均未通过这组5% Holm调整检验；这不是说六策略没有赚钱。

**第三至第五讲的13个去重候选**：重现第六讲的主动收益、标准误、区间与五种 p 值口径，最大绝对误差约 `7.11e-15`。405条日收益中，这13个候选的平均主动收益全部为负；不是校正太严才把它们筛掉。注意，它们不是上面的原六策略。

**第七讲选优风险**：显式取2025-01-13至2026-09-04的400条记录，排除窗口外5条，10块、252个切分。严格低于中位数81.75%，恰好中位数8.33%，包含并列的PBO90.08%，与原结果一致。这个数说明该候选家族中历史选优不稳定，不是预测未来有90.08%的概率亏钱。

本次没有重新运行选股和交易回测。因为交易规则没改，重新跑相同成交链来寻找收益提升并不能验证这些工具的作用；本次重点是对归档结果进行可复现复核。

### C. 已知没有优势的反例：验证误判控制

固定种子42，模拟10,000次，每次尝试20个独立、没有真实优势的正态检验统计量。在5%阈值下：

- 不校正：64.85%的重复实验至少误判一个方案有效。
- Holm校正：5.04%的重复实验至少误判一个方案有效。

这不是市场回测，也不是说真实市场能达到同样误判率。它验证了一个明确用途：在设定成立的反例中，工具能避免把大量尝试产生的偶然显著当成优势。真实候选相关、收益分布变化、家族漏报等限制仍然存在；尤其BH需要相应的依赖条件，不能把所有调整方法视为同一种保证。

### D. 原交易系统没有被改动

对本轮开始前的交易、回测、模型、因子、关键配置与前向会话文件做前后哈希对比：**381个文件一致**。另核对前向会话冻结代码与账本链。未重写既有持仓、交易记录、策略参数或冻结协议。

这证明的是本次迁移隔离性，不是证明原交易系统已满足真实实盘全部要求。

## 4. 没合并什么，为什么，什么时候再合

### 第一讲：最小方差优化器与整套配置实验

**为什么暂缓**：会改变持仓权重；主分支已经有等权、夏普和风险平价以及集中度分析，需要整合现有接口，而不是再平行堆一个优化器。原实验降低了波动，但没有证明增加收益。

**何时可作为可选功能合并**：统一现有权重接口；补齐协方差不足、奇异矩阵、优化失败、权重上限不可行、现金及交易约束测试；同一信号、同一基准、同一成本与现有配置对照。默认启用则另需冻结参数和新的前向证据。工具合并与策略启用是两次验收。

### 第二讲：完整本地风格指数构建器

**为什么暂缓**：依赖特定基础池字段、规模和账面市值比分组、流通可用性等约定，还不是官方标准因子的复刻。

**何时合并**：把股票池、加权方式、调仓日历、财务可见性与缺失报价规则做成独立协议，补齐统一接口与复现测试。当前归因工具已经能接收调用方准备好的合规代理序列。

### 第三、四讲：把新信号注册进默认融合、改变股票池

**为什么暂缓**：定义正确不等于有可靠超额；加入毛利润资产比、跳过近期动量等会改变研究对象。第四讲的非金融可比样本也不能偷偷变成基础可交易池的行业偏好。

**何时合并**：先独立注册为默认关闭的研究候选，声明数据覆盖和适用行业；用统一时间、股票池、基准和成本做增量对照。要加入六策略则需正式策略版本变更、参数冻结及未参与设计的前向验证，不能追改已经封存的账户。

### 第五讲：行业上限留现金、重新分配、排名补位

**为什么暂缓**：三种处理会产生不同持仓、现金和换手，属于组合决策变化，不是只读检查。原实验不能支持“加行业上限必然降低回撤”。

**何时合并**：统一约束处理顺序，覆盖不足候选、全行业拥挤、停牌、涨跌停、资金不足、整手与科创板股数限制；在相同信号下分别比较收益、现金、集中度、换手和成本，再作为显式可选模式接入。

### 第一至第五讲涉及的目标权重回测接口

**为什么暂缓**：研究分支扩展了 `target_weight_plans`，直接改变回测执行路径，不能顺便夹带进只读工具迁移。尤其需要明确全现金目标、日期匹配、缺失行情预算留现金，以及与现有单票/行业/换手上限的交互。

**何时合并**：单独做执行路径验收；未传入新参数时原默认结果逐项一致；传入等权目标时复现原等权路径；各种异常情况下资金、持股、费用对账通过。合并不等于自动改用它。

### 第六、七讲：自动淘汰门禁、自动切换冠军

**为什么不合并为交易规则**：统计显著性不是交易指令，CSCV不是前向收益保证；不能把这次诊断又变成一套更复杂、更严苛的自动准入制度。

**何时考虑**：只有提出明确的经济逻辑、完整策略协议和新验证计划时，才作为新研究讨论。没有“等几天自动合并”的安排，也不设必须上自动冠军策略的目标。

## 5. 下一步原则

现有六策略继续按原冻结规则做每日前向纸面交易。新回测完成后，可以用本次独立入口补一份研究检查报告；只有几天的前向收益，继续记录，不强行做显著性结论。

七讲的收获首先是**更清楚地知道结果为什么产生、哪里可能不可信**。本次已把这部分变成可调用、可测试的工程能力；真正会改变买卖名单和资金分配的部分，留到相应验收通过后再接入。
